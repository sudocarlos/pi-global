# CONTRIBUTING.md

Derive every rule from what the codebase already does, not from aspiration. Document the actual pattern first; note intended improvements separately so they are not mistaken for current convention.

Cover:

- **Coding style** — naming, layout, idioms, error handling, testing expectations
- **UX patterns** — interaction flows, messaging and copy tone, accessibility
- **UI guidelines** — components, spacing, color and typography tokens, responsive rules

Keep it living: when a review or the user corrects a convention, update `CONTRIBUTING.md` so the next contributor — human or agent — inherits the fix.
